Roles & permissions

config/authorization.json is the Git-backed, ITIL-recommended baseline. Check or clear boxes below to grant or revoke an action for a role in this tenant — changes are stored as overrides on top of that baseline, so "Reset to recommended" can always bring a role back to it. Per-CI-class CMDB permissions are configured separately below. administer and platform_administer are only shown for admin: every admin panel page requires the admin role itself, so granting these to another role can never open panel access, regardless of this setting. security_administer stays editable for agent/manager since it also independently governs CMDB Network Discovery access. Rows marked not yet enforced aren't checked by any route yet — the operations they'd nominally cover (ticket deletion, approval decisions, task close/reopen, and similar) are already authorized through separate, fixed role and team-membership rules, so toggling these here has no effect for any role; shown for visibility into the full ITIL action catalog, not as a live control. create is a partial exception: it's enforced for REST API v1 clients but not the browser UI.
